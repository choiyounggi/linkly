# LNPL for VS Code (skeleton)

Diagnostics from `lnpl lsp` and syntax highlighting for `.lnpl` files. This is an unpublished
skeleton: it does nothing beyond diagnostics, the verb Quick Fix, hover, and highlighting.

## Run it from this folder

1. `pip install` lnpl so `lnpl` is on your PATH, or set `lnpl.serverPath` to the absolute path of
   `.venv/bin/lnpl`. The extension runs that command with the single argument `lsp`. That
   console script is a copy: after editing `impl/lnpl/`, run `pip install --force-reinstall
   --no-deps .` again, or an older `lnpl` without `lsp` starts and the client gives up.
2. Run `npm install` in this folder. It creates `node_modules/`, which is git-ignored.
3. Open this folder in VS Code and press F5 to start an Extension Development Host.
4. Open a `.lnpl` file. Diagnostics appear as underlines, and the lightbulb offers the verb
   replacement for an `unknown-verb` warning.

## Generated files

`syntaxes/lnpl.tmLanguage.json` is generated by `python scripts/gen_plugin_references.py` from
`impl/lnpl/grammar.py`. Never hand-edit it; `python scripts/gen_plugin_references.py --check` fails
when it is stale.

## Known limits

- Each document compiles alone. Sibling files of an RFC-0031 directory module are not read, so
  names declared there show up as errors.
- Highlighting is layout-free. A line-head `cache` in a `performance` clause (`cache 5m`) or in a
  spec expectation (`cache written`) is coloured as a verb.
- Hover only answers on workflow-step verbs.
- Not published to the Marketplace.
