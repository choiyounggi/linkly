# lnpl 0.2.0 재측정 보고서 — 원 실측 대비 개선 효과 정량

원 실측(커밋 `713a4cb`, 2026-08-05, `qa/REPORT.md` — 판정 No-Go) 대비
재측정(커밋 `6d84bd6`, 2026-08-07, 이슈 #43~#50 구현 + RFC-0014~0017 이후 main)의
개선 효과 보고. 1차 소스는 Wave 1 재측정 4개 워크트리의 DELTA.md·FINDINGS.md이며
새 측정은 하지 않았다. 46건 F-기록의 전건 정규화 표·클러스터 배정·집계 원자료는
`qa/rerun/report-appendix/friction-matrix.md`(이하 appendix)가 정본이다. 이
보고서의 모든 판정 문장은 F-번호/N-번호/DELTA 행/evidence 경로를 인용한다.

케이스 표기: 원 보고서의 t1~t4와 재측정의 r1~r4는 같은 케이스다
(r1=t1 inventory-order, r2=t2 payment-refund, r3=t3 batch-report,
r4=t4 rate-notify).

## 1. Executive Summary

**원 판정: No-Go** — "lnpl 0.2.0은 플랫폼 전체로는 프로덕션 사용 불가. …
미수용 blocker가 5건 있다"(원 REPORT §1).

**갱신 판정: No-Go → 조건부 Go(도메인 한정 Ship-with-known-issues) — 배치·집계
워크로드만 잔여 Block.** blocker 5건 중 3건 해소·2건 부분(§4 추적표). 릴리스
게이트의 결과는 Ship / Ship-with-known-issues / Block 셋뿐이므로, 각 도메인의
판정은 다음과 같다: 요청-응답 CRUD·값 기반 규칙(r1 "프로덕션 사용 가능(상태 전이
자동화 제외)"), 결제·민감정보(r2 "사용 가능(조건부)" — 조건 2건), 가드+spec
검증(r4 "판정 반전 — spec 원형 3시나리오 PASS"), 시간창 정책(r2 F-5 해소)은
**각 케이스 판정이 명시한 조건을 known-issues로 소유자가 수용하는 경우
Ship-with-known-issues**다. 배치·집계는 **Block 유지**(r3 "배치·집계 워크로드는
여전히 사용 불가 — 단 blocker 2건이 각각 절반 열렸다"). 조건 미수용 시 해당
도메인도 Block이다(수용자 없는 known-issue는 Block — 원 REPORT §1과 같은 규칙).

세 줄 근거:

1. **blocker 5건 중 3건 해소, 2건 부분(전부 증적 인용 — §4).** 가드 우변 필드
   참조(r1 F-1)·산술/할당(r1 F-2)·카드번호 원문 노출(r2 F-7)은 재현 동형
   커맨드가 원 기대 동작을 냈고, 집계(r3 F-1)와 배치 트리거(r3 F-2)는 절반만
   열렸다(파생값 실계산·선언 메타데이터 도달, sum/count·실행기 잔존).
2. **46건 마찰 중 해소 33 · 부분 7 · 잔존 6(appendix §2 재계산).** 원 무음 실패
   클러스터 C1~C5는 C1(spec 무음 병합)·C4(`--field` 무경고 무시)가 전건 해소,
   C2·C3·C5가 부분으로 전환됐다(§3.2) — "초록인데 의미가 조용히 증발한다"는 원
   §4의 명제가 성립하는 표면이 opt-in 게이트(`--strict`)·구조화 레코드
   (`skipped[]`)·컴파일 거부로 대부분 닫혔다.
3. **케이스 판정 4건 중 3건 상향, 1건 부분 개선(§5).** 원 유일 spec 단계
   FAIL(t4)은 원형 3시나리오 8/8 PASS로 반전됐고(r4 DELTA "원 유일 FAIL 반전"),
   재시도는 케이스 내 비교로 r3 12→3·r4 8→1로 줄었으며 r1은 총량 6→6이나
   "blocker 우회 0건"으로 성격이 바뀌었다(r1 DELTA 재시도 표).

신규 마찰 14건(major 5건)과 잔존 마찰 13건 + #51은 §6에 전건 목록화했다 —
개선 서사에 가려지지 않아야 하는 실측 결과다.

## 2. 측정 설계

**동일 케이스·동일 요구.** 원 실측의 4케이스(능력 축: 다중 엔티티 CRUD+수량
규칙+상태 전이 / 민감정보 마스킹·정책·경계값 / 집계·배치 트리거 / 가드 런타임
실측 — 원 REPORT §2 표)를 같은 제품 요구로 재수행했다. r4는 소스·payload가
원형과 동형임을 기계 확인했다(r4 FINDINGS: "워크플로 8스텝 diff 무출력, payload
7종 cmp 동일").

**동일 페르소나.** "공개 문서만으로 개발하는 LLM-only 개발자" — AGENTS.md 라우팅
+ plugins/lnpl/skills/ 문서 + examples/ 샘플만 사용, 플랫폼 무수정(각 FINDINGS
헤더). r2는 rfcs/0015·0016을 소스에 추가했는데(r2 FINDINGS 차터), 이는 재측정
순도의 한계로 §7에 기록한다.

**원형 표현 규칙.** 원 실측에서 "우회의 누적"으로 도달한 초록과 구별하기 위해,
재측정은 제품 요구의 원형 표현(예: r2 "제품 요구 5개가 전부 원형대로 선언")
성립 여부를 판정 기준으로 삼았다.

**대조 방법 — DELTA 판정 규율.** 각 케이스는 원 F-기록 전건(46건)에 대해 원 재현
커맨드의 동형 재실행으로 판정했다. 판정 어휘(각 DELTA 룰릭 원문): **해소** = 원형
표현 성립 + 원 증상 소멸, 증적 필수(r2: "원 마찰의 재현 커맨드 동형이 원 기대
동작을 내고 raw 인용 가능") / **부분** = 개선됐으나 제약 잔존(1줄 명시) / **잔존**
= 동일 실패 양식 재현. r3은 "사전조사·구현 커밋 메시지는 근거로 쓰지 않았다"를
명시했고, 대조군(examples/shorten.lnpl 전 단계 rc=0)으로 실패의 케이스 귀속을
증명했다(r3 FINDINGS 헤더).

| C | 원 명명 · 원 심각도 | 상태 | 근거(잔존 요소) |
|---|---------------------|------|------------------|
| C1 | spec 블록 무음 병합 · major(4/4 관측) | **해소** | 4건 전소 — 블록별 독립 케이스(r1F7·r2F10·r3F5·r4F4); 원 재현은 rc=2+교정 지시(r3 evidence/07-probe-d1) |

| C3 | 선언·참조의 무음 증발 · major | **부분** | 연쇄 가드 파싱 에러·미선언 참조 컴파일 거부·`--strict`(r2F2·r4F2·r3F3 해소); JSON 진단 스트림·등급 부재(r3F8 부분) |
| C4 | `--field` 오키 무경고 무시 · major | **해소** | 2건 전소 — rc=2+유효 키 목록(r1F9·r4F3) |

| C10 | 미문서 규칙·문서-구현 불일치 · major(4/4 관측) | **부분** | 8건 중 7건 해소(가드 스코프·다단어·복수형·워크플로 id·guarded 예제·CLI 커버리지·KB 라우팅); 진단 파일:라인 부재(r4F11 잔존) |

원 §4의 계열 구도로 보면: **무음 실패 계열(C1~C5)은 해소 2·부분 3** — 잔존
요소가 전부 "기본값이 여전히 관대"(opt-in 게이트) 또는 "검사 스코프 한정"
유형이고, **표현력 공백 계열(C6~C8)은 해소 1·부분 2** — 잔존이 배치·집계
본론(C6·C8)에 몰려 있다. 문서·진단 계열(C10)은 1건(파일:라인)만 남았다.

원 §6의 예측 — "1~4가 완료되면 무음 실패 계열(C1~C5)이 관측 가능해져 …

부분 잔존(기본값·스코프·등급)이 C2·C3·C5의 부분 상태로, 5·7의 잔존(집계·실행기)이
C6·C8의 부분 상태로 그대로 이어진다(§3.2).

## 4. blocker 5건 추적

원 REPORT §1이 명시한 미수용 blocker 5건(t1 F-1·F-2, t2 F-7, t3 F-1·F-2)의
전건 추적. 해소 기제는 각 DELTA/FINDINGS 행이 명시한 RFC·이슈만 인용했다.

|---------|----------------------|-----------|-------------|---------------------------------------------------------------|

### 6.3 남은 갭과 전면 Go까지의 경로

전면 Go를 막는 것은 §1 기준 배치·집계 Block과, 조건부 Go 도메인들의
known-issue 수용 여부다. 남은 갭(전부 오픈 상태 확인, 이슈 제목 인용):

1. **#25(OPEN)** "실제 capability 백엔드 부재 — postgres/redis/jwt가 Fake/no-op"
   — 이번 재측정 스코프 밖(4케이스 전부 Fake 백엔드 위 실측)이므로 프로덕션
   배포 전 별도 검증 축이다.
2. **#26(OPEN)** "서빙 계층 부재 — OpenAPI는 생성되나 실제로 요청을 처리하는
   서버가 없음" — t3 F-2 잔존 절반의 소관("issue #26 … owns the executor" — r3
   DELTA F-2). 스케줄 실행기가 여기 속한다.
3. **집계 로드맵** — 행 집합 집계(sum/count)는 RFC-0015 §Alternatives에 "넣지
   않는 이유+후속 이슈 제안"으로 기록돼 있으나(r3 DELTA F-1,
   rfcs/0015-value-semantics.md:322 인용), authoring 라우팅에서 그리로 가는
   포인터가 0건이라 LLM-only 개발자는 발견 불가(r3 evidence/03-vocab-survey-diff.md §D12).
4. **#51(OPEN)** — §6.1 마지막 행. 관측기 층 비대칭으로 추적 중.
5. **r3 자동화 후보 갭 6건**(r3 DELTA ④ 전사): ① 진단 등급 도입+`--strict` 등급

## 7. 측정의 한계

1. **재측정 순도 — 학습 효과 혼입.** 같은 페르소나 규율이라도 재측정 세션들은 원
   실측 기록(`qa/cases/<case>/`)을 대조 기준으로 읽었다(각 DELTA 헤더). 원형
   표현이 1회 컴파일에 통과한 것(r2)·재시도 감소(r3 12→3, r4 8→1)에는 언어
   개선뿐 아니라 "무엇이 함정인지 아는 상태"의 학습 효과가 혼입될 수 있다.
   재시도 수치는 이 한계 위에서 읽어야 한다.
2. **문서 개선과의 혼합 효과.** 재측정 커밋에는 #50 문서 보강(naming.md·
   cli-surface.md 등 — r1 FINDINGS 헤더)이 포함돼, "문서 라우팅으로 도달"(r2
   "문서 라우팅 11홉·컴파일 1회") 류의 개선은 언어 기능과 문서의 합산 효과다 —
   이 보고서는 둘을 분리 계측하지 않았다(원 실측도 동일).
3. **페르소나 소스 확대.** r2는 rfcs/0015·0016을 지식 소스에 포함했다(r2 FINDINGS
   차터) — 원 실측의 "AGENTS.md+skills+examples만"보다 넓다. r2 N-4가 기록했듯
   시간 문법 발견이 RFC 번호 인지에 의존하므로, RFC를 모르는 개발자의 마찰은
   이번 측정보다 클 수 있다. 반면 r4는 impl/ 미열람을 명시해(r4 "측정 순도
   캐비앗") 원 실측의 열람 오염이 재발하지 않았다.
4. **원 한계의 승계(원 REPORT §7).** 표본 크기(4케이스·단일 커밋 6d84bd6·케이스당
   1세션), 단일 페르소나(LLM-only), 미측정 축(성능·동시성·장기 운영·실 부하 —
   판정은 기능·표현력·관측성 축 한정)은 그대로 승계된다. 측정 컨트롤은 이번에도
   유효하다: r3이 대조군(examples/shorten.lnpl compile·run rc=0)을 재수행해
   실패·제약의 케이스 귀속을 유지했다(r3 FINDINGS 헤더).
5. **판정의 비대칭.** "해소"는 원 재현 커맨드 동형의 반증이라는 강한 기준이지만,
   "부분"의 잔존 절반이 도메인 본론인 경우(r3)와 주변부인 경우(r1)가 같은 어휘로
   묶인다 — 도메인 영향은 §5.1의 케이스 판정 원문이 정본이다.
