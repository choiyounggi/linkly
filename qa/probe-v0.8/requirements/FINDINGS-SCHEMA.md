# FINDINGS / METRICS 스키마 — 케이스 공통

t6(종합 보고서)이 다섯 케이스를 기계적으로 대조하려면 형식이 같아야 한다. 아래 절
제목과 표 열은 **그대로** 쓴다.

## 1. FINDINGS.md

```markdown
# FINDINGS — <case>

환경: 커밋 <sha>, lnpl <version>, python <ver>, 드라이버 <목록/none>, dev_doctor rc=<n> (evidence/00-env.md)
조건: 블랙박스(requirements/README.md §2), impl/ 열람 <n>회(각 F-항목에 표기), impl/ 수정 0건

## Scorecard

| 단계 | 결과 | 증적 경로 | 재시도 수 |
|------|------|-----------|-----------|
| authoring | PASS/FAIL/N/A | evidence/01-authoring.md | <n> (내역) |
| compile(--strict=warning) | | evidence/02-compile.md | |
| modeA run | | evidence/03-run.md | |
| spec | | evidence/04-spec.md | |
| openapi | | evidence/05-openapi.md | |
| serve(실 HTTP) | | evidence/06-serve.md | |
| <시나리오 고유 단계…> | | | |

## 요구사항 커버리지

| R | 요구 | 판정 | 근거(evidence 경로 + 실행 출력 인용) |
|---|------|------|--------------------------------------|
| R1 | … | 충족 / 부분 / 불가 / 우회(의미 손실: …) | evidence/… |

## Frictions

### F-1: <한 줄 제목>
- 단계: <Scorecard 단계> | 심각도: blocker / major / minor | 축: <아래 §2 축 태그 1개>
- 재현: <정확한 명령 + 입력 파일 + rc + 출력 발췌>
- 기대 vs 실제: <어느 문서 어느 줄을 따랐고 무엇을 기대했는지> vs <실제>
- 재시도: <n> | 우회: 성공/실패 — <무엇을 했는지, 의미 손실 여부>
- 근인(impl 열람): <파일:줄 — 열람했을 때만; 안 했으면 이 줄 생략>
- 보완 제안: <플랫폼이 무엇을 바꾸면 이 마찰이 사라지는가 — LLM 특화 언어 관점>

## 케이스 판정

**<Ship / Ship-with-known-issues / Block>** — <한 문단 근거; known-issue면 소유자가 수용해야 하는 조건을 번호로 열거>
```

심각도 정의:
- **blocker**: 요구사항을 우회로도 충족 못 함, 또는 조용히 틀린 결과(초록인데 값이 다름).
- **major**: 우회는 됐지만 의미 손실이 있거나 3회 이상 재시도가 필요했음.
- **minor**: 우회 1~2회로 해소, 의미 손실 없음. 문서 오류 포함.

## 2. 축 태그 (F-항목당 정확히 1개)

| 태그 | 뜻 |
|------|-----|
| `expr` | 언어 표현력 — 요구를 어휘·문법으로 말할 수 없음 |
| `diag` | 진단 — 틀렸는데 조용하거나, 진단이 있어도 고칠 방향을 안 알려줌 |
| `doc` | 스킬·문서·예제가 틀리거나 빠짐 — LLM이 문서만 보고 못 씀 |
| `rt` | 런타임 의미론 — 파싱은 되는데 실행이 기대와 다름 |
| `ops` | 운영 — 드라이버·serve·배포·마이그레이션·관측 |
| `perf` | 성능 — 실행 시간·처리량·메모리 |
| `llm` | LLM 특화 — 토큰 비용, 라운드 수, 문법 추측 실패, 컨텍스트에 실어야 하는 문서량 |
| `maint` | 유지보수 — 변경 요청 반영 비용, 회귀 탐지력, 리팩터링 가능성 |

## 3. METRICS.md

```markdown
# METRICS — <case>

| 지표 | 값 | 측정 방법 |
|------|-----|-----------|
| 소스 줄 수 (.lnpl 또는 .py, 공백·주석 제외) | | `grep -cve '^\s*$' …` |
| 파일 수 | | |
| authoring 라운드 (편집→재실행 사이클 총계) | | evidence/01 합산 |
| 실행한 CLI 명령 수 | | evidence 전수 |
| 첫 컴파일 성공까지 라운드 | | |
| 첫 spec 전건 통과까지 라운드 | | |
| spec 시나리오 수 / 단언 수 | | |
| 요구사항 충족 / 부분 / 불가 / 우회 (개수) | | 커버리지 표 집계 |
| 결함 탐지: spec이 잡은 것 / 사람이 실행 출력을 보고 잡은 것 / 못 잡고 지나간 것 | | |
| 읽은 문서 (파일 목록과 대략 줄 수) | | 워커가 실제로 Read한 것 |
| 변경 요청(R-change) 반영: 바뀐 줄 수 / 라운드 / 기존 spec 중 깨진 것 | | |
| 벽시계 시간 (시작~FINDINGS 완성) | | 세션 타임스탬프 |
| 토큰 | (코디네이터가 트랜스크립트로 기입) | token-report.sh |
```

값이 없으면 `N/A(이유)`. 추정치는 `~` 접두.
