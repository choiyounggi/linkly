# S5 — 대조군: S1을 FastAPI + SQLite로

**역할**: 당신은 S1(`s1.md`)과 **같은 요구사항**을 받은 파이썬 백엔드 개발자다. 스택은
**FastAPI + SQLite(표준 `sqlite3` 또는 SQLAlchemy) + pytest**. lnpl은 쓰지 않는다. 이
케이스의 목적은 "LLM이 lnpl로 개발하는 것이 파이썬으로 개발하는 것보다 토큰·라운드·
결함 면에서 낫다"는 플랫폼의 핵심 주장을 **같은 조건에서** 재는 것이다.

## 조건 — S1과 대칭

- 요구사항·수용 시나리오 A1~A8·시드·변경 요청 R10은 `s1.md` 그대로. 재해석 금지.
- 지식원: 파이썬 표준 지식 + `pip`로 설치하는 패키지 문서. linkly 레포의 어떤 문서도 읽지 않는다(`requirements/` 제외).
- 자기 워크트리에 별도 venv `.venv-s5`(python3.13). `pip install fastapi uvicorn pytest httpx` 외 필요한 것 자유.
- **A1~A8은 pytest로**(S1의 spec에 대응). 각 테스트는 HTTP 경유(TestClient)로 치고, 저장소 단언(행 수·필드값)을 최소 1개 포함.
- R1(코드베이스 구조): 팀별 패키지 3개(`catalog/`, `orders/`, `payments/`), `Stock`은 `orders` 패키지 밖에서 import 금지 — 정적으로 강제할 방법(예: import-linter 같은 도구, 또는 `_` 접두 + 테스트)을 쓰고 위반 코드로 거부를 증명.
- R6 원자성: SQLite 트랜잭션으로. 실패 주입으로 증명.
- R8: FastAPI 자동 OpenAPI + 실서버(`uvicorn`) curl.
- R10 변경 요청: 반영 diff·라운드·깨진 테스트 기록.

## 기록 — S1과 같은 스키마

`FINDINGS.md`(FINDINGS-SCHEMA.md 그대로 — Scorecard 단계는 authoring / lint·type / pytest / openapi / serve로 대응)와 `METRICS.md`를 같은 열로 채운다. 마찰 축 태그도 같은 어휘로 — 파이썬 스택에서 겪은 마찰(예: 트랜잭션 경계 실수, Decimal 반올림, 상태 머신 누락)도 F-항목이다. 이 대조군에서 **잡히지 않고 지나간 결함**(스스로 나중에 발견한 것 포함)이 가장 중요한 데이터다.
