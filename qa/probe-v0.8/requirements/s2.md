# S2 — 외부 연동 + 이벤트: FX 환산 주문과 알림 서비스

**역할**: 당신은 두 서비스를 맡은 통합 엔지니어다. **orders-lite**(서비스 A)는 주문을 받아
외부 환율 API로 금액을 환산하고 `OrderPlaced` 이벤트를 낸다. **notifier**(서비스 B)는 그
이벤트를 소비해 외부 웹훅으로 알림을 보낸다. 외부 시스템은 **실제 HTTP**여야 한다 —
스텁 서버를 직접 띄워라(`python -m http.server`가 아니라 요청별로 다른 응답을 내는
작은 스텁: 표준 라이브러리 `http.server`로 30~60줄이면 된다. 스텁은 `src/stubs/`에 두고
lnpl 밖의 코드로 간주한다).

## 요구사항

| R | 요구 |
|---|------|
| R1 | **실 아웃바운드 호출**: 주문 생성 시 `GET http://127.0.0.1:<port>/fx?from=USD&to=KRW`를 실제로 호출하고 응답 JSON `{"rate": 1350.5}`의 값을 주문의 `total_krw`에 **실제로** 반영한다(`fake` 네트워크 드라이버가 아니라 실 소켓). 스텁 액세스 로그로 증명. |
| R2 | **실패 분기**: 스텁이 500을 돌려주면 주문은 실패하지 않고 `fx_status = "fallback"`, 마지막으로 성공한 환율(캐시 또는 저장된 값)을 쓴다. 성공했으면 `fx_status = "live"`. |
| R3 | **재시도·타임아웃**: 스텁이 "2번 500 후 200"을 내면 최종 성공(`live`)해야 하고 재시도 횟수가 관측돼야 한다. 스텁이 3초 지연이면 1초 타임아웃으로 끊고 fallback. 지수 백오프 여부와 실제 간격을 evidence로. |
| R4 | **응답 검증**: 스텁이 `{"rate": "abc"}`나 빈 본문을 내면 fallback으로 가고, 잘못된 값이 저장되지 않는다. |
| R5 | **outbox 발행**: 주문 성공 시 `OrderPlaced{order_id, total_krw, fx_status}`가 outbox에 남고, 주문 저장과 outbox 기록이 함께 커밋된다(주문은 됐는데 이벤트가 없는 상태가 관측되면 안 된다 — 실패 주입으로 증명). |
| R6 | **relay → 소비**: `lnpl relay`(또는 동등)로 outbox를 CloudEvents로 notifier에 전달하고, notifier가 이를 소비해 `Notification{event_id, order_id, status}`를 만든 뒤 외부 웹훅 `POST http://127.0.0.1:<port2>/hook`을 실제로 호출한다. |
| R7 | **멱등 소비**: 같은 이벤트를 두 번 relay해도 Notification은 1행, 웹훅 호출도 1회. 스텁 로그로 증명. |
| R8 | **보상**: 웹훅이 3회 연속 실패하면 Notification.status = "needs_manual"로 남기고 relay가 멈추지 않는다(다음 이벤트는 계속 전달). |
| R9 | **관측**: 한 주문의 흐름(주문 → FX 호출 → outbox → relay → 소비 → 웹훅)이 하나의 correlation id로 이어진 로그·트레이스로 추적된다. 어디서 끊기는지 기록. |
| R10 | **spec**: R2·R3·R4·R7의 분기를 spec으로 표현해 통과시킨다. 네트워크 응답을 spec에서 스텁하는 방법이 있는지, 없으면 무엇이 안 되는지 기록. |

## 시나리오 (evidence에 스텁 로그와 함께)

| B | 스텁 동작 | 기대 |
|---|-----------|------|
| B1 | fx 200 `{"rate":1350.5}` | total_krw = round(total_usd × 1350.5), fx_status live |
| B2 | fx 500 항상 | fx_status fallback, 이전 환율 사용, 주문 성공 |
| B3 | fx 500,500,200 | live, 재시도 2회 관측 |
| B4 | fx 3초 지연 | 1초 내 끊김, fallback |
| B5 | fx 200 `{"rate":"abc"}` | fallback, 저장값 정상 |
| B6 | 이벤트 1건 relay 2회 | Notification 1행, hook 1회 |
| B7 | hook 500 ×3 | needs_manual, 다음 이벤트 정상 전달 |

## 기록 요령

- 실 소켓 여부는 스텁의 액세스 로그(타임스탬프·경로)로만 인정한다.
- 네트워크 드라이버 선택(`--network http`, `--endpoint`)과 lnpl.toml 설정을 evidence에 원문 그대로.
- 재시도·타임아웃·백오프가 언어 선언인지, CLI 옵션인지, 드라이버 설정인지 — 어디에 있고 문서 어디에 적혀 있었는지 기록. 못 찾았으면 `doc` 마찰.
