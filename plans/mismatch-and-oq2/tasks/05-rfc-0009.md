## Inputs

- **The defect this closes.** RFC-0002 §Open Questions ② still reads
  *"가드 조건식의 표현력 — `Condition`은 현재 비교식+1~4토큰 구가 전부다."*
  RFC-0008 changed `Condition` to `Presence | Comparison`, so that sentence is now
  false. RFC-0008's `Updates:` list names `RFC-0002 §Full grammar` and
  `RFC-0003 §Guard` — **not** §Open Questions.
  RFC-0007 §2.2 rule 2: *"지목하지 않은 절과 모순되면 안 된다. 모순이 필요하면 그 절도
  `Updates:` 목록에 지목해야 한다. **지목 없는 모순은 개정이 아니라 결함이다.**"*
- **Why a new RFC rather than editing RFC-0008** (D9): RFC-0008 is `Accepted`, and
  adding a section to its `Updates:` list changes the effective contract
  (RFC-0007 §2.2 rule 3 defines the contract as the target's sections replaced by
  the updating RFC's text). That is a substantive change, and RFC-0007 §2.1 keeps
  those out of in-place edits.
- **Why `Updates` and not `Supersedes`** (D10): only one section of RFC-0002
  changes; the rest is still the contract, so RFC-0002 stays `Accepted`
  (RFC-0007 §2.2 relation table).
- **Rule 4 obligation** (D11): the updating RFC's section must contain the text
  *after* substitution — not "change X to Y". So reproduce the whole five-item
  list with ② rewritten and 1, 3, 4, 5 **verbatim**.
- RFC-0002 §Open Questions, current text, five items — read it from
  `rfcs/0002-syntax.md` and copy items 1, 3, 4, 5 exactly.
- **The seven mandatory sections (D13).** RFC-0007 §7: *"신규 **설계** RFC는 아래
  블록을 그대로 복사해 시작한다(프로세스 RFC는 §1의 면제 대상). 7개 섹션의 이름과
  순서는 고정이며 글자 단위로 일치해야 한다(섹션 추가·삭제·개명 금지)."* RFC-0009 is a
  design RFC — the exemption is for process RFCs — so all seven appear, in order:

  `## Status` · `## Motivation` · `## Guide-level Explanation` ·
  `## Reference-level Specification` · `## Examples` · `## Alternatives` ·
  `## Open Questions`

  `rfcs/0008-guard-conditions.md` has all seven; use it as the shape reference.
- Decisions that bind you: **D9**, **D10**, **D11**, **D12** (do not touch
  RFC-0008), **D13** (seven sections), **D15** (Status recorded as `Accepted`).

## Steps

1. Create `rfcs/0009-guard-condition-open-question.md`.

2. `## Status`:
   ```
   - Status: **Accepted** (RFC-0009, 2026-08-02)
   - Updates: RFC-0002 §Open Questions
   ```
   Nothing else in that block. Do **not** write `Supersedes`.

3. `## Motivation` — state the defect exactly as it is, in the repo's Korean
   register (RFC-0008 is written in Korean; match it):
   - RFC-0008 갱신한 `Condition` 정의와 RFC-0002 §Open Questions ②가 모순된다.
   - RFC-0008의 `Updates:` 목록은 그 절을 지목하지 않았다.
   - RFC-0007 §2.2 규칙 2에 따라 이는 **결함**이며, 이 RFC가 그 관계를 보충해 해소한다.
   - RFC-0008 자체는 수정하지 않는다 (그 본문은 여전히 옳다).

4. `## Guide-level Explanation` — two or three paragraphs for a reader who has
   not followed the history: what a guard condition may look like today
   (`token missing`, `counter >= 10`), that the 1~4-token phrase form was removed
   by RFC-0008 because nothing could evaluate it, and that this RFC exists only to
   put RFC-0002's open-question list in agreement with that. No new rules here.

5. `## Reference-level Specification` — one section titled so it is unmistakably
   the replacement text, e.g. `### RFC-0002 §Open Questions (치환 후 최종 텍스트)`.
   Inside it, the full five-item list:
   - items **1, 3, 4, 5**: copied verbatim from RFC-0002. Do not reword, do not
     renumber, do not "improve" them. They are unchanged contract.
   - item **2**: rewritten as resolved. It must say that `Condition` is now
     `Presence | Comparison` per RFC-0008, and that the 1~4-token phrase
     alternative was removed because no evaluator implemented it.

     On what stays open, be precise — **RFC-0008 §Open Questions 3 is
     `논리 결합의 표현력` and covers negation and and/or only.** 멤버십 검사 appears
     nowhere in RFC-0008. So write: 부정·논리 결합은 RFC-0008 §Open Questions 3이
     이어받고, **멤버십 검사는 어느 RFC도 추적하지 않으므로 이 항목이 그대로 남긴다**.
     Claiming RFC-0008 tracks all three would be a false cross-reference in the
     document whose entire purpose is fixing a false cross-reference.

6. `## Examples` — RFC-0007 §6 requires examples to use the golden "Login"
   scenario, and §5 forbids redefining it (reference only). Show, against
   `examples/login.lnpl`'s vocabulary, one condition the grammar admits
   (`when token missing`) and one it now rejects (`when latency exceeds budget`
   → `ConditionError: invalid comparator 'exceeds'`, measured). That is the
   behavioural content of the resolved question.

7. `## Alternatives` — record the two rejected paths, one line each:
   - RFC-0008을 직접 수정해 `Updates:` 목록에 절을 추가 → RFC-0007 §2.1 위반
     (Accepted RFC의 실질 변경).
   - RFC-0002를 전면 대체(Supersedes) → §2.2가 `Updates`를 신설한 이유와 정면으로
     어긋난다. 한 절만 바뀌는데 문서 전체를 종결시킨다.

8. `## Open Questions` — `없음.` This RFC settles one bookkeeping defect and
   opens nothing.
